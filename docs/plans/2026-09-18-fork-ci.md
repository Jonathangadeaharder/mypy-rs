# Fork CI setup (2026-09-18)

The working repo is the fork `Jonathangadeaharder/mypy-rs`; `origin` points
at the fork and `upstream` at `codenkirch/mypy-rs`. Protecting the parent
needs the owner account (the token there is not admin and runner
registration returns 403), so the fork is the new home.

## Workflows

| Workflow | Trigger | Jobs |
| --- | --- | --- |
| `pr-gate.yml` | PR to main | `pr-gate` (extensions, self-check, parity suites), `lint-changed` |
| `merge-gate.yml` | PR to main, dispatch | `codeql`, `merge-battery` (cmdline + slow families) |
| `native-kernel-parity.yml` | PR to main (path-filtered), dispatch | `changes`, `parity`, `parity-mirror`, `parity-symtable-flip`, `parity-typeops`, `parity-ast` |
| `code-review.yml` | `pull_request_target` | `ocr-review` on the self-hosted runner |
| `nightly.yml` | `17 3 * * *`, dispatch | `full-battery`, `rust-workspace`, `deep-lint-and-docs`, `report` |

## Required checks

`lint-changed`, `pr-gate`, `codeql`, `merge-battery` — the checks that run
on every PR. The `native-kernel-parity` jobs are path-filtered, so they
cannot be required: a required status context that never appears leaves
`mergeable_state` blocked forever. They still gate kernel PRs by running.

`ocr-review` runs under `pull_request_target`, so it executes the workflow
file from the base branch. A fix to the gate therefore only takes effect
once merged; on the PR that carries the fix the check shows the old
behaviour.

## Self-hosted runner

`~/runners/mypy-rs`, launchd `actions.runner.mypy-rs.ephemeral.mypy-rs`.
The manager had two faults: the repository-runners API returned 403 until
the fork existed (fixed by forking), and `~/runners/mypy-rs/bin` was a
symlink into another repo's install, so the listener refused to
reconfigure. Repointing `bin`/`externals` at same-root copies fixed it.

## OCR gate status value

OpenCodeReview v1.12.5 reports a successful review as `status:
"complete"`; the inherited gate accepted only `"success"` and so failed
every clean review. Both are accepted now; a review with findings still
fails the check.

## Known native-seam divergences (deselected, tracked)

`merge-battery` runs the `pytest-cmdline` family, which no workflow ran
before. Two cases are genuine native-seam gaps and are deselected with a
reference (mirroring the `#585` precedent):

- #4 — native resolver vs multiple `--package-root`
  (`testPackageRootMultiple1`);
- #5 — native parser emits generic `Invalid syntax`
  (`testParallelRunWithSyntaxError`).

Deselected, not hidden: both are open issues.

## Deferred
